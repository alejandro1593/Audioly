# PLAN PROYECTO AUDIOLY - POSTGRESQL (pg + Sequelize)

## 1. TECNOLOGÍA PRINCIPAL
- **Base de Datos**: PostgreSQL 15 (Neon en la nube o Docker/local)
- **ORM**: Sequelize
- **Backend**: Node.js + Express.js
- **Autenticación**: JWT (access + refresh) + bcrypt

## 2. MODELOS DE DATOS (TABLAS)

### Users
```sql
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  username VARCHAR(50) UNIQUE NOT NULL,
  email VARCHAR(100) UNIQUE NOT NULL,
  password VARCHAR(255) NOT NULL,
  avatar VARCHAR(255) DEFAULT 'default-avatar.png',  -- o /uploads/avatar-<ts>.png
  role VARCHAR(20) DEFAULT 'user' CHECK (role IN ('user', 'artist', 'admin')),
  createdAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updatedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### Artists
```sql
CREATE TABLE artists (
  id SERIAL PRIMARY KEY,
  userId INTEGER REFERENCES users(id) ON DELETE SET NULL,
  name VARCHAR(100) NOT NULL,
  image VARCHAR(255),
  bio TEXT,
  verified BOOLEAN DEFAULT FALSE,
  monthlyListeners INTEGER DEFAULT 0
);
```

### Albums + SavedAlbums
```sql
CREATE TABLE albums (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  artistId INTEGER NOT NULL REFERENCES artists(id) ON DELETE CASCADE,
  coverImage VARCHAR(255),
  releaseDate DATE,
  genre VARCHAR(50),
  description TEXT,
  plays INTEGER DEFAULT 0
);

CREATE TABLE saved_albums (          -- álbumes guardados del usuario
  id SERIAL PRIMARY KEY,
  userId INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  albumId INTEGER NOT NULL REFERENCES albums(id) ON DELETE CASCADE,
  savedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(userId, albumId)
);
```

### Songs + Likes + Plays + Comments
```sql
CREATE TABLE songs (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  artistId INTEGER NOT NULL REFERENCES artists(id) ON DELETE CASCADE,
  albumId INTEGER REFERENCES albums(id) ON DELETE SET NULL,
  duration INTEGER,
  url VARCHAR(500),
  audioKey VARCHAR(255),            -- clave del stream propio / SoundHelix / Jamendo / spotifyId
  coverImage VARCHAR(255),
  genre VARCHAR(50),
  plays INTEGER DEFAULT 0,
  lyrics TEXT,
  releaseDate DATE,
  isExplicit BOOLEAN DEFAULT FALSE
);

CREATE TABLE user_liked_songs (
  id SERIAL PRIMARY KEY,
  userId INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  songId INTEGER NOT NULL REFERENCES songs(id) ON DELETE CASCADE,
  likedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(userId, songId)
);

CREATE TABLE listening_history (    -- alimenta Mix, Recap y recomendaciones
  id SERIAL PRIMARY KEY,
  userId INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  songId INTEGER NOT NULL REFERENCES songs(id) ON DELETE CASCADE,
  playedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  durationPlayed INTEGER
);

CREATE TABLE comments (             -- comentarios por canción
  id SERIAL PRIMARY KEY,
  songId INTEGER NOT NULL REFERENCES songs(id) ON DELETE CASCADE,
  userId INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  content TEXT NOT NULL,
  createdAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### Playlists + Songs + Colaboradores + Likes + Shared
```sql
CREATE TABLE playlists (
  id SERIAL PRIMARY KEY,
  name VARCHAR(100) NOT NULL,
  description TEXT,
  userId INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  coverImage VARCHAR(255),
  isPublic BOOLEAN DEFAULT TRUE,
  shareToken VARCHAR(64) UNIQUE,   -- para compartir por link público
  createdAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updatedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE playlist_songs (
  id SERIAL PRIMARY KEY,
  playlistId INTEGER NOT NULL REFERENCES playlists(id) ON DELETE CASCADE,
  songId INTEGER NOT NULL REFERENCES songs(id) ON DELETE CASCADE,
  position INTEGER NOT NULL DEFAULT 0,  -- orden por drag & drop
  addedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(playlistId, songId)
);

CREATE TABLE playlist_collaborators (  -- listas colaborativas
  id SERIAL PRIMARY KEY,
  playlistId INTEGER NOT NULL REFERENCES playlists(id) ON DELETE CASCADE,
  userId INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  addedAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(playlistId, userId)
);

CREATE TABLE playlist_likes (
  id SERIAL PRIMARY KEY,
  playlistId INTEGER NOT NULL REFERENCES playlists(id) ON DELETE CASCADE,
  userId INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  createdAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(playlistId, userId)
);
```

### Follows + Notifications
```sql
CREATE TABLE user_follows (
  id SERIAL PRIMARY KEY,
  followerId INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  followingId INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  createdAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(followerId, followingId)
);

CREATE TABLE notifications (        -- con actor para mostrar su avatar
  id SERIAL PRIMARY KEY,
  userId INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,   -- receptor
  actorId INTEGER REFERENCES users(id) ON DELETE CASCADE,           -- quien ejecuta la acción
  type VARCHAR(50),                -- 'follow' | 'collaborator'
  message TEXT,
  isRead BOOLEAN DEFAULT FALSE,
  relatedId INTEGER,               -- playlistId para 'collaborator'
  createdAt TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_notifications_user ON notifications(userId, isRead);
```

### Podcasts + Episodios
```sql
CREATE TABLE podcasts (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200) NOT NULL,
  hostId INTEGER NOT NULL REFERENCES artists(id) ON DELETE CASCADE,
  description TEXT,
  coverImage VARCHAR(255),
  genre VARCHAR(50)
);

CREATE TABLE podcast_episodes (
  id SERIAL PRIMARY KEY,
  podcastId INTEGER NOT NULL REFERENCES podcasts(id) ON DELETE CASCADE,
  title VARCHAR(200) NOT NULL,
  audioUrl VARCHAR(500),
  duration INTEGER,
  releaseDate DATE,
  description TEXT
);
```


## 4. FUNCIONALIDADES CLAVE (SQL)

### Mix automático (getMix: daily | flashback)
- **Daily**: peso por recencia `exp(-días / 30)` sobre `listening_history`, uniones con likes, y relleno genero/artista.
```sql
SELECT s.id, s.title,
       1.0 / (1 + EXTRACT(EPOCH FROM (CURRENT_TIMESTAMP - h.playedAt)) / 86400) AS w
FROM listening_history h JOIN songs s ON s.id = h.songId
WHERE h.userId = :userId
ORDER BY w DESC LIMIT :limit;
```
- **Flashback**: `GROUP BY songId ... ORDER BY COUNT(*)  DESC` (más escuchadas de siempre).

### Recap estilo Wrapped (getRecap / getTopItems)
- Window functions para top canciones, artistas y álbumes del año.

### Seguimiento & Notificaciones
- `INSERT INTO user_follows` + `INSERT INTO notifications(type='follow')`
- Colaboración: `INSERT INTO playlist_collaborators` + `notifications(type='collaborator', relatedId=playlistId)`

### Búsqueda y sugerencias
- `ILIKE '%q%'` en songs.title, artists.name, playlists.name
- Sugerencias limitadas por rol/usuario

## 6. SUBIDA DE ARCHIVOS (multer)
- Middleware `upload.middleware.js`: destino `backend/uploads/`, límite 20 MB, formatos imagen + audio
- `POST /api/users/avatar` guarda `avatar-<ts>-<rand>` y actualiza `users.avatar`
- Registro de canciones vía admin/upload con portada y/o audio
- `server.js` sirve `/uploads` estático (los navegadores resuelven con `mediaUrl` del frontend)

## 7. MIDDLEWARES
- JWT Authentication (+ refresh automático en frontend)
- Role-based access control (user / artist / admin)
- CORS
- Error handling
- File upload (multer)
- Validation
